# OmniAgent OS 威胁模型规范

> **文档版本**: v1.0.0 | **最后更新**: 2026-04-25 | **责任团队**: 安全工程组

## 1. 系统边界与信任假设

### 1.1 系统边界

OmniAgent OS 信任边界分为三层：完全可信（微内核、安全飞地）、半可信（Agent 池、服务层、桌面合成器、硬件设备）、不可信（用户应用、网络、云 AI API、物理环境）。

### 1.2 信任假设

| 组件 | 信任级别 | 假设 |
|------|---------|------|
| **微内核** | 完全可信 | 代码经过形式化验证，攻击面最小 |
| **安全飞地** | 完全可信 | 硬件隔离或软件隔离保证 |
| **系统服务** | 半可信 | 可能存在漏洞，遵循最小权限原则 |
| **Agent** | 半可信 | 可能被恶意提示注入，需要沙箱隔离 |
| **用户应用** | 不可信 | 任意代码，完全隔离 |
| **网络** | 不可信 | 所有网络输入需验证和过滤 |
| **云 AI API** | 不可信 | 可能返回恶意内容，需要输出验证 |
| **硬件设备** | 半可信 | 可能存在固件漏洞，驱动程序需最小化 |
| **物理环境** | 不可信 | 假设攻击者可能物理接触设备 |

## 2. 威胁参与者

| 参与者 | 能力 | 动机 | 目标 |
|--------|------|------|------|
| **外部攻击者 (TA-EXT)** | 发送网络数据包、利用已知漏洞、中间人攻击 | 数据窃取、破坏 | 远程入侵系统 |
| **恶意 Agent (TA-AGENT)** | 沙箱内执行任意计算、通过授权 API 访问资源 | 越权操作、数据泄露 | 逃逸沙箱、提权 |
| **被攻陷服务 (TA-SVC)** | 拥有该服务所有权限、处理该服务所有 IPC | 横向移动、权限提升 | 攻击其他服务或内核 |
| **恶意用户** | 运行任意应用、利用 UI 漏洞 | 获取其他用户数据 | 跨用户攻击 |
| **物理攻击者** | 物理访问、固件修改 | 数据提取、持久化后门 | 绕过软件安全机制 |

## 4. STRIDE 分析

### 4.1 微内核

| 威胁类型 | 具体威胁 | 缓解措施 |
|---------|---------|---------|
| **S** | 伪造 IPC 消息来源 | 消息签名 + 内核验证发送者身份 |
| **T** | 篡改 IPC 消息内容 | 消息完整性校验 (HMAC) |
| **R** | 否认发送过 IPC 消息 | 审计日志记录所有 IPC |
| **I** | 通过 IPC 泄露内核数据 | 内核数据不通过 IPC 传递 |
| **D** | 通过 IPC 耗尽内核资源 | IPC 速率限制 + 配额管理 |
| **E** | 通过系统调用获取内核权限 | 最小权限 + 能力验证 |

### 4.2 Agent 系统

| 威胁类型 | 具体威胁 | 缓解措施 |
|---------|---------|---------|
| **S** | Agent 伪造身份 | Agent ID 绑定到安全飞地密钥 |
| **T** | 篡改 Agent 代码或数据 | 代码签名 + 数据加密存储 |
| **R** | Agent 否认执行过操作 | 审计日志 + Agent 行为追踪 |
| **I** | Agent 读取未授权数据 | 能力令牌 + 数据访问控制 |
| **D** | Agent 耗尽系统资源 | 资源配额 + 速率限制 |
| **E** | Agent 逃逸沙箱 | 沙箱隔离 + 内核强制执行 |

### 4.3 桌面环境

| 威胁类型 | 具体威胁 | 缓解措施 |
|---------|---------|---------|
| **S** | 伪造窗口或 UI 元素 | 窗口签名 + 合成器验证 |
| **T** | 篡改输入事件 | 输入事件签名 + 来源验证 |
| **R** | 否认用户操作 | 输入审计日志 |
| **I** | 窗口间数据泄露 | 窗口隔离 + 剪贴板控制 |
| **D** | 恶意窗口占用资源 | 窗口资源限制 |
| **E** | 通过 UI 漏洞提权 | 最小权限 + 沙箱隔离 |

### 4.4 云 AI 接口

| 威胁类型 | 具体威胁 | 缓解措施 |
|---------|---------|---------|
| **S** | 伪造云 API 响应 | TLS + API 响应签名 |
| **T** | 篡改 AI 模型输出 | 输出验证 + 安全过滤 |
| **R** | 否认 API 调用 | API 调用审计日志 |
| **I** | 泄露用户数据到云端 | 数据脱敏 + 最小化发送 |
| **D** | 云 API 不可用 | 本地降级 + 缓存策略 |
| **E** | 通过 AI 响应获取权限 | 输出沙箱 + 权限隔离 |

### 5.1 TH-001: Agent 沙箱逃逸 (详细)

攻击向量：利用 IPC 消息处理中的整数溢出、通过共享内存映射越界读写、利用系统调用参数验证缺陷、通过资源耗尽触发内核 OOM 后的竞争条件。

缓解措施：内核形式化验证、IPC 消息边界检查、系统调用参数双重验证、Agent 资源配额硬限制、安全飞地隔离关键数据、定期模糊测试。

### 5.2 TH-007: 提示注入 (详细)

攻击向量：在用户输入中嵌入恶意指令、通过云 AI 响应注入恶意内容、利用 Agent 工具调用链中的漏洞、通过多轮对话逐步提升权限。

缓解措施：输入验证和清洗、输出安全过滤、工具调用权限分级、操作确认机制（高风险操作）、Agent 行为审计、提示注入检测模型。

```rust
/// 提示注入检测器
pub struct PromptInjectionDetector {
    patterns: Vec<Regex>,
    ai_detector: LocalDetector,
}

impl PromptInjectionDetector {
    pub fn detect(&self, input: &str) -> InjectionResult {
        for pattern in &self.patterns {
            if pattern.is_match(input) {
                return InjectionResult::Detected { confidence: 0.9,
                    pattern: pattern.as_str().to_string() };
            }
        }
        let ai_score = self.ai_detector.score(input);
        if ai_score > 0.8 {
            return InjectionResult::Suspected { confidence: ai_score };
        }
        InjectionResult::Clean
    }
}
```

### 7.2 模型安全

| 威胁 | 描述 | 缓解措施 |
|------|------|---------|
| **模型投毒** | 恶意修改 AI 模型权重 | 模型签名 + 完整性验证 |
